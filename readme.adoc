= Neo4j 3D Graph Explorer

Connect to any Neo4j database over Bolt, run any Cypher, and render the result as a
3D force-directed graph you can rotate, zoom and rearrange.

One self-contained file — `neo4j-3d.html`. No build step, no dependencies to install.
Open it directly (`open neo4j-3d.html`) or serve it (`python3 -m http.server`).

Built on https://github.com/vasturiano/3d-force-graph[3d-force-graph] (three.js) and the
Neo4j JavaScript driver, both pinned from a CDN.

== Connecting

Encryption comes from the URI scheme. Do *not* also pass an `encrypted` option — modern
drivers reject both together.

[cols="1,3"]
|===
| `bolt://localhost:7687` | local server, unencrypted (the default)
| `neo4j+s://<host>` | Aura, or any server with a valid certificate
| `neo4j+ssc://<host>` | self-signed certificate
|===

The browser speaks Bolt over WebSocket, which constrains the plaintext case: an `https://`
page cannot open a `ws://` connection. To reach a local database, open this file over
`file://` or `http://localhost` — not from an https host.

The password is only written to `localStorage` if you tick the box.

== Rendering any result

It does not assume a result shape. It walks every field of every record — recursing into
lists and maps — and picks out graph entities using the driver's own type predicates:

[source,javascript]
----
if (neo4j.isNode(v))         addNode(v);
if (neo4j.isRelationship(v)) addRel(v);
if (neo4j.isPath(v))         for (const seg of v.segments) { ... }
----

So all of these work with no configuration:

[source,cypher]
----
MATCH (n)-[r]->(m) RETURN n, r, m            // entities
MATCH p = ()-[*1..2]-() RETURN p             // paths
CALL db.schema.visualization()               // entities nested inside lists
MATCH (n)-->(m)                              // scalar fallback: no entities returned,
RETURN n.name AS source, m.name AS target    // so `source`/`target` columns are used
----

Nodes are keyed on `elementId` (a string) rather than `id(n)` — element ids can exceed
`2^53`, so calling `.toNumber()` on an identity is lossy. Neo4j `Integer`, temporal, point
and vector values are converted to primitives before display, so the details panel shows
`300` rather than `{low: 300, high: 0}`. Long arrays such as embeddings are summarised.

Relationships whose endpoints the query didn't return are kept and given placeholder
nodes rather than being dropped; the status line reports how many.

`$limit` is bound to the limit box, so `LIMIT $limit` works in your own queries. The same
value also caps rows client-side.

== Moving it around in 3D

* drag the background to rotate, scroll to zoom, right-drag to pan
* drag a node to reposition it; with *Pin nodes where I drop them* on, it stays there
  (`fx/fy/fz`) instead of springing back. *Unpin all* releases them
* *Camera controls* switches between trackball (free rotation), orbit (keeps the horizon
  upright) and fly (WASD/RF + mouse look)
* click a node for its properties, with *Focus* to fly the camera to it

Colour, size and caption are driven by dropdowns populated from the properties actually
present in the result, so `pagerank`, `community` and the like appear automatically when
they exist. Sizes are normalised onto a fixed range, since raw property values span
arbitrary scales.

== Seeing the relationships

Dense graphs live or die on how readable the edges are, so three controls target that:

* *Theme* — dark or light. Light is usually clearer once there are more edges than nodes:
  dark lines on white hold contrast better than pale lines on black.
* *Relationship contrast* — link opacity.
* *Relationship thickness* — at `0` (the default) links draw as constant-width 1px lines
  that stay visible however far you zoom out. Above `0` they become 3D tubes, which look
  better up close but shrink into invisibility at distance.

One trap worth naming: set opacity in `linkOpacity` *only*. If you also bake an alpha into
`linkColor` (`rgba(...)`) the two multiply and the relationships all but disappear.

== History

This repository previously held a set of fixed demo pages, each hardcoding one query
against a Game of Thrones dataset, plus a small React 2D viewer. `neo4j-3d.html` replaces
